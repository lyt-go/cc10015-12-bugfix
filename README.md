# 多维分析实验平台

面向实验设计、指标计算、样本分析、效果评估与结论发布的数据分析实验平台。

这是一个前后端分离的管理平台：前端 Vue 3 + Vite + TypeScript，后端 FastAPI（Python）。
两边各自独立启动，前端 dev server 已关掉自动打开页面，启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/              统一请求封装
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false）
├── backend/                  FastAPI（Python） 后端
│   ├── app/routers/          每个业务模块一组接口
│   ├── app/services/         业务规则与状态流转
│   └── app/store.py          内存数据仓库与示例数据
├── .gitignore
└── docker-compose.yml
```

## 启动

### 后端

```bash
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
./run.sh
```

健康检查：`curl http://127.0.0.1:8000/api/health`

### 前端

```bash
cd frontend
npm ci
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，
需要自己访问。`/api` 由 vite 代理到后端 `http://127.0.0.1:8000`。

## 约定

- 每个模块的前端页面在 `frontend/src/views/<模块>/index.vue`，后端接口在
  `backend/app/routers/<模块>.py`，业务规则在 `backend/app/services/<模块>.py`。
- 列表接口统一返回 `{ items, total, page, size }`，动作接口统一返回 `{ ok, message }`。
- 状态流转只允许在 `app/services` 里改，路由层不做业务判断。

## 数据导出与 V012 导出文件清单

数据导出模块把「读取导出任务 → 裁剪实验范围 → 生成文件清单 → 回查」做成一条可核对链路：

- **范围归属**：`app/services/scoping.py` 统一定义范围解析与裁剪口径；导出任务、AB 结果、
  文件清单都按实验编号裁剪，范围外记录不会出现在列表、详情或下载文件里。
- **字段与口径**：`app/services/metric_catalog.py` 从指标定义收敛指标键、字段标签与精度位数；
  清单、文件元数据和指标定义核对接口共用这一份口径，避免三处各写一套。
- **V012 清单事务**：`POST /api/data_export/manifests` 先在暂存区写入文件与分片，成功后再整体发布；
  任何异常都会回滚、清理暂存分片，并在 `data_export_manifest_archive` 留档。
- **同批次多范围**：`按范围拆分` 生成两个独立文件并各自声明实验范围；`合并文件` 生成一个文件并附范围分区边界。
- **续写**：已发布文件只允许补写缺失分片，已写入分片的校验与内容不会被改写。
- **回查**：下载文件是 JSON，`metadata` 同时写入字段清单、实验范围（含完整范围与本次查看范围）和指标口径；
  `GET /api/data_export/manifests/{batch}/verify` 与 `GET /api/metric_def/export-caliber-check?batch=...`
  分别核对清单完整性和跨模块口径一致性。

列表与详情接口都接受 `?scope=EXPE-0001`（逗号分隔可传多个）作为允许查看的实验范围；
不传表示不裁剪。
